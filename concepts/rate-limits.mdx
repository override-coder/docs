Each request counts toward several limits. The API rejects it if it exceeds any of them.

The values below are defaults; your deployment may use different limits.

## Shared limits

Global, source IP, endpoint, account, API key, and trading limits can all apply to a request. Each request counts once toward each shared limit.

Global, source IP, and endpoint limits also cover unauthenticated requests and unknown routes. A request can return `429 RATE_LIMITED` before credential validation or a `404`; a `429` does not confirm that its credentials are valid. CORS preflight requests remain `204` responses.

| Bucket | Limit | Applies to |
|---|---:|---|
| Global | 6,000 requests / minute | All OpenAPI traffic |
| Global burst | 1,500 requests / 10 seconds | All OpenAPI traffic |
| IP | 60 requests / minute | Source IP |
| IP burst | 20 requests / 10 seconds | Source IP |
| Endpoint | 120 requests / minute | HTTP method + matched route template |
| Endpoint burst | 40 requests / 10 seconds | HTTP method + matched route template |
| Account | 120 requests / minute | Authenticated account |
| Account burst | 40 requests / 10 seconds | Authenticated account |
| API key | 120 requests / minute | API key id |
| API key burst | 40 requests / 10 seconds | API key id |

Unknown routes share a single endpoint bucket. Different resource IDs on the same matched route do not create separate endpoint quotas.

## Rate-limit response

When a request exceeds a limit, the API returns HTTP `429` with `code=RATE_LIMITED`.

| Header | Description |
|---|---|
| `Retry-After` | Seconds to wait before retrying |
| `X-RateLimit-Limit` | The limit for the bucket that rejected the request |
| `X-RateLimit-Remaining` | Remaining requests in the current window, usually `0` |
| `X-RateLimit-Reset` | Seconds until the current bucket resets |

Use `Retry-After` when present. If it is absent, use exponential backoff with jitter; do not retry immediately. On every retry, generate a fresh timestamp, nonce, and signature. For a repeated write, keep the original API key, idempotency key, and request intent. See [Idempotency](/concepts/idempotency).

## Invalid signatures

Repeated invalid signatures can return `429 RATE_LIMITED`. The default threshold is 10 failures within 10 minutes. This counter applies only to failed signatures, so it does not lock out requests with valid signatures. Source IP, account, endpoint, and nonce checks still apply. These signature-failure responses do not include the retry headers listed above.
