Each request counts toward several limits. The API rejects it if it exceeds any of them.

The values below are defaults; limits for your environment may differ. Confirm them with PolyCop.

## Shared limits

Global, source IP, endpoint, account, API key, and trading limits can all apply to a request.

Rate limits also apply to unauthenticated requests. A `429 RATE_LIMITED` response does not confirm that the credentials are valid.

| Limit scope | Limit | Applies to |
|---|---:|---|
| Global | 6,000 requests / minute | All OpenAPI traffic |
| Global burst | 1,500 requests / 10 seconds | All OpenAPI traffic |
| IP | 60 requests / minute | Source IP |
| IP burst | 20 requests / 10 seconds | Source IP |
| Endpoint | 120 requests / minute | HTTP method and endpoint; resource IDs share the same limit |
| Endpoint burst | 40 requests / 10 seconds | HTTP method and endpoint; resource IDs share the same limit |
| Account | 120 requests / minute | Authenticated account |
| Account burst | 40 requests / 10 seconds | Authenticated account |
| API key | 120 requests / minute | API key id |
| API key burst | 40 requests / 10 seconds | API key id |

Different resource IDs on the same endpoint share its limit.

## Rate-limit response

When a request exceeds a limit, the API returns HTTP `429` with `code=RATE_LIMITED`.

| Header | Description |
|---|---|
| `Retry-After` | Seconds to wait before retrying |
| `X-RateLimit-Limit` | The request limit that was exceeded |
| `X-RateLimit-Remaining` | Remaining requests in the current window, usually `0` |
| `X-RateLimit-Reset` | Seconds until a request subject to this limit is expected to be allowed; a relative delay, not a Unix timestamp or a full quota reset |

Use `Retry-After` when present. If it is absent, use exponential backoff with jitter; do not retry immediately. On every retry, read the current timestamp, generate a new nonce, and recompute the signature. For a repeated write, keep the original API key, `Idempotency-Key`, and request body. See [Idempotency](/concepts/idempotency) for each operation’s deduplication scope.

## Invalid signatures

Repeated invalid signatures can return `429 RATE_LIMITED`. The default threshold is 10 failures within 10 minutes. Validly signed requests remain subject to the other request limits and authentication rules. These signature-failure responses do not include the retry headers listed above.
